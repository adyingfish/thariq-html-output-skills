# 设计

> "HTML *is* the medium your design system ships in, so it's the natural format
> for talking about it. Tokens become swatches, components become contact
> sheets, and the artifact can be fed straight back into the next prompt." —
> Thariq
>
> 「HTML *本身*就是你的设计系统最终交付所用的媒介，所以它是谈论设计的天然格式。令牌变成色样，
> 组件变成接触表，而这份产物可以径直喂回到下一条提示词里。」—— Thariq

谈论设计最诚实的格式，就是设计最终交付所用的那个媒介。把东西渲染成它自己，绝不要渲染成它的
截图或对它的描述。

## Thariq 的两个 demo

- **活性设计系统** ——「从仓库里取出的颜色、字号阶梯和间距令牌，渲染成你可以直接复制的色样。」
- **组件变体** ——「把一个组件的每种尺寸、状态和意图，铺排在一张表上供审阅。」

## 构建活性设计系统

- 每个令牌类别一节：颜色、字体、间距、圆角、阴影、动效。
- **把每个令牌渲染成它自己**：颜色作色样，字体以真实字号呈现真实文字，间距作可见的带标签
  的留白，阴影投在卡片上。`#5B6CFF` 挨着它的色样，每次都胜过孤零零的 `#5B6CFF`。
- 每个色样/样本上放一个**复制按钮**——点击复制值，shift 点击复制令牌名（`--color-accent-500`），
  或放两个按钮。这份产物一半是参考、一半是工具；复制动作正是要点，也正是它能「径直喂回下一条
  提示词」的原因。
- 有代码库就**从代码库里取**——读 Tailwind 配置 / 主题文件 / CSS 变量，而非凭空发明看似合理的
  令牌。忠于事实源就是一切；一套有偏差的系统比没有更糟。

## 构建组件接触表

- 一个组件，所有状态摆在一页上：尺寸 × 意图 × 状态（悬停、聚焦、禁用、加载中、错误）。按轴分组
  ——每行一种尺寸，每列一种意图。
- 渲染**真实的**组件（或最接近的 HTML/CSS 近似），每个变体下方附上产生它的 props。
- 别跳过那些「古怪」的状态（加载中、空、错误）——那恰恰是设计系统忘了规定、而工程现编的部分。
- 一张表只放一个组件。多组件页会变成一场巡览，那是另一种产物。

## 跨产物的复用

一份设计系统产物值得保存下来（`design-system.html`），并喂进此后每一个产物作为 CSS 变量的来源。
这是一次性的工作，却能让它之后的一切都保持品牌一致。当一个有真实视觉身份的项目第一次要求 HTML
输出时，就建议这么做。
