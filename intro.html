镜头，
而非分桶。

Lenses,
not buckets.

桶是不透明、互相隔离的；镜头是半透明、可叠加的。这个技能不把请求塞进某一个类别，而是先感知它的形状，再透过每一面合用的镜头去构建。它同样在意 Thariq 最在意的那件事——知道何时根本不该用 HTML。

Buckets are opaque and walled off from each other; lenses are translucent and stackable. This skill doesn't file a request into one category — it perceives its shape first, then builds through every lens that fits. It cares just as much about the thing Thariq cared about most — knowing when not to reach for HTML at all.

本页面本身就是一个产物：单个自包含的 .html，离线可用，色彩只在承载意义处出现。技能要求的，它都守住了。

This page is itself an artifact: a single self-contained .html, works offline, color only where it carries meaning. Everything the skill asks for, it holds to.

触发：一种感知，而非关键词匹配

Triggering: a perception, not a keyword match

我即将写的东西，是否有一个会被线性文本压平的形状——读者会「扫一眼」它的 Markdown 版，但会「真正阅读」它的 HTML 版吗？

Does the thing I'm about to write have a shape that linear text would flatten — would the reader "skim" a markdown version but "actually read" an HTML one?

整篇文章都围绕这一个问题展开。所以触发器问的是一种感知——而非「请求里有没有出现『报告』这个词」。九面镜头在这里是给你所见形状命名的词汇表，不是一张你必须匹配其中一行的路由表。

The whole post turns on this one question. So the trigger asks about a perception — not "does the request contain the word report." The nine lenses are a vocabulary for naming the shape you saw, not a routing table you match one row of.

若答案确实为否——它只是一句话、一段代码、一条命令——那就保持 Markdown。一个把每条提示词都转成 HTML 的技能，恰恰是 Thariq 所担忧的那个东西。

If the answer really is no — it's a single sentence, a snippet, one command — then stay in markdown. A skill that turns every prompt into HTML is exactly the thing Thariq worried about.

九面镜头

Nine lenses

九面镜头，每一面对应一种内容的形状。把九种分开、而不揉成更少几类，本身就是一种判断——不同的形状值得不同的看法。镜片上那句话，是 Thariq 一眼看穿这种形状的观察；你构建时先得认出形状，这些话帮你认。

Nine lenses, each for one shape of content. Keeping the nine distinct rather than collapsing them into fewer is itself a judgment — different shapes deserve different ways of looking. The line on each lens is Thariq's own observation that sees through that shape; you have to recognize the shape before you build, and these help you recognize it.

镜头会叠合

Lenses stack

这是整个技能的核心，也是 Thariq 自己的设计。看他对实施计划这个 demo 的描述——它表面是一个类别，实则同时是四面镜头叠在一起：

This is the heart of the whole skill, and Thariq's own design. Look at how he describes the implementation plan demo — on the surface one category, in truth four lenses stacked at once:

"Milestones on a timeline, a data-flow diagram, inline mockups, the risky code, and a risk table — the plan you hand off." —— Thariq，描述「实施计划」demo — Thariq, describing the "implementation plan" demo

构建逻辑很简单：数出所有合用的镜头 → 读取每个被点名的参考文件 → 让主导镜头（这里是「探索」）确定骨架，其余镜头在骨架内贡献各自的层。拿不准时，多透过几面镜头，而非更少。重叠的地方色彩加深——那正是 Thariq 那些最好的例子获得密度的方式。

The build logic is simple: count every lens that fits → read each named reference → let the dominant lens (here, Exploration) set the skeleton, and the others contribute their layers inside it. When unsure, look through more lenses, not fewer. Where they overlap the color deepens — that's how Thariq's best examples get their density.

他的顾虑，就是我们的设计

His worry is our design brief

"you don't need to do much to get Claude to do this."

「你并不需要做太多，就能让 Claude 实现这一点。」 —— Thariq Shihipar

Thariq 在原文里直言，他担心有人把这篇文章变成一个机械的 /html 技能。那样的技能会抹掉他真正在乎的东西——判断力：何时该用，何时该放手。

In the post itself Thariq says he worried someone would turn it into a mechanical /html skill. Such a skill would erase the thing he actually cared about — judgment: when to reach for it, and when to leave it alone.

所以对这篇文章最深的领会，不是逐条照搬它，而是不把它做成一本规则手册。这个技能宁可是最小的脚手架——给出框架和例子，然后让开，信任模型自己看出每个产物想要成为的样子。原文给的本就是例子，而非规则。

So the deepest reading of the post is not to copy it line by line, but to not turn it into a rulebook. This skill would rather be the smallest scaffolding — give framing and examples, then get out of the way and trust the model to see what each artifact wants to be. The post gave examples, not rules.

它不是「总是用 HTML 回答」。重点从来不是格式，而是：对许多人们如今要求智能体产出的东西，Markdown 那种线性、无色、静止的形状会主动遮蔽内容，而 HTML 解除了这层束缚。本技能是识别，而非反射。

It isn't "always answer in HTML." The point was never the format; it's that for many things people now ask agents to produce, markdown's linear, colorless, static shape actively obscures the content, while HTML lifts that constraint. This skill is recognition, not reflex.

配得上被读

Earning the read

无论由哪几面镜头构建，每个产物都守住下面这一小组品质。它们不是官僚主义——每一条都是「你只会略读的文档」与「你会真正阅读的文档」之间的分水岭。

Whichever lenses build it, every artifact holds to this small set of qualities. They aren't bureaucracy — each one is the watershed between "a document you'd only skim" and "one you'd actually read."

01单个自包含文件A single self-contained file无构建步骤；CSS、JS、SVG 全在一个 .html 里，直接在浏览器打开。No build step; CSS, JS, and SVG all in one .html, opens straight in a browser.
02离线可用Works offline查看时不依赖网络请求。No network requests needed to view it.
03移动端能存活Survives on mobile含 viewport，窄屏不塌。Has a viewport; doesn't collapse on a narrow screen.
04真实布局，而非堆叠标题Real layout, not stacked headings比较就分列，时间轴就画时间轴，差异就渲染差异。A comparison gets columns, a timeline gets drawn, a diff gets rendered.
05五秒内可读Readable in five seconds标题、一句框架、然后是实质。立刻知道自己在看什么。Title, one framing line, then the substance. You know what you're looking at at once.
06默认克制Restraint by default平静的排版，色彩只在承载意义处出现。Calm typography; color only where it carries meaning.
07编辑器导出回文本Editors export back to text不可妥协。以「复制 / 下载」收尾，合上闭环。Non-negotiable. End with copy / download to close the loop.

自足交接

Self-sufficient handoff

  • 路由给子任务时，打包三样东西即可无额外上下文构建：
  • (a) 用户原始请求；

  • When routing to a subtask, package three things and it builds with no extra context:

  • (c) the full text of each named reference.
